# Test plan: validation of AI image detectors

Date: 3 Nov 2026, updated 5 Nov 2026. Prompts: [TEST_PROMPTS.md](TEST_PROMPTS.md). Results: [TEST_RESULTS.md](TEST_RESULTS.md).

## Goal

Measure how often each detector (a) calls an AI image AI and (b) wrongly calls a real photo AI, on images that are independent of the models' own benchmarks, and find the best way to combine detectors.

## Test set

| Class | Count | Source | Selection |
|---|---|---|---|
| Real, first set | 50 | Open Images (Hugging Face `vikhyatk/openimages-bbox`, test split), Flickr photos from 2018 | 5 per subject; no people; short side 640 px or more; JPEG; subject by CLIP zero-shot; most typical photos (`scripts/fetch_openimages_real.py`) |
| Real, second set | 337 | Same dataset | 35 per subject targeted; no people; short side 640 px or more; ratio at most 2.2; **random** among qualifying photos; first set excluded. Mountain 30 and street 27 (scarce); saved as original `.jpg` in `own_test/real2/` |
| AI | 50 | Generated by us in free tiers | 10 per tool, 5 tools, prompts in `TEST_PROMPTS.md` |

- Subjects (10): mountain, coast, forest, street, interior, food, flower, animal, monument, vehicle.
- Real photos predate photorealistic generators. Open Images has only JPEG (580 of 580 sampled).
- No people in real or AI images. Phone photos were not used.
- Not used: COCO, ImageNet, LAION, FFHQ, CelebA (in the training data of Community Forensics or OpenFake, which Bombek1 trained on). Wikimedia Commons is blocked on this network.

## Scoring and combination

- Each model gives a score 0 to 1; AI if the score is at or above the cutoff. Default cutoff 0.5.
- Metrics: real photos wrongly called AI, AI images caught, correct overall, AUC, seconds per image on CPU. Ranges are 95% Wilson intervals.
- **Combined score:** average of Smaug and Bombek1 log-odds, equal weights. Log-odds = ln(p / (1 - p)), with p limited to 0.000001 to 0.999999.
- **Cutoff from real photos only:** all real photos are split, seeded and stratified by subject, 25% cutoff part (97) and 75% final part (290). For a false-alarm limit L, the cutoff is the score that only L of the cutoff-part real photos exceed. AI images are never used for the cutoff; they only measure the catch rate.
- **Bands and limits (decided 5 Nov 2026):** accuse limit **2%**, clear limit **5%** (for now), both settings. Likely AI above the accuse cutoff; unclear between the two; likely real below the clear cutoff. Default cutoffs from all 387 real photos: accuse -1.74, clear -3.16. The limits were chosen from 500 random splits of the real photos (`analyze_layouts.py`); reasons in TEST_RESULTS section 7. `analyze_combined.py` reports the research bands at 1% and 10%.
- Community Forensics was dropped after the first result (10% of AI images caught).

## Pipeline

| Step | Script (in `image-detection/scripts/`) |
|---|---|
| Sample real photos | `fetch_openimages_real.py` (second set: `--pick random --exclude-csv real_sources.csv --out-name real2`) |
| Build JPEG, shrunk and screenshot versions and the first split | `build_testset.py` |
| List the second real set | `build_real2_manifest.py` |
| Score Smaug | `score_smaug.py` (saves each score as it goes and resumes) |
| Score Community Forensics | `score_commfor.py` (`--selfcheck` reproduces the authors' example) |
| Score Bombek1 | `score_bombek1.py` (`--selfcheck` uses 20 OpenFake images; saves as it goes and resumes) |
| First-round report by split | `analyze_results.py` |
| Combined result (one split) | `analyze_combined.py` |
| Band limits (500 random splits) and default cutoffs | `analyze_layouts.py` |
| Format check | `build_format_check.py`, `analyze_formats.py` |

Raw scores: `image-detection/results/*.csv`. Test images are local only (gitignored).

App code (ReviewIt repo, folder `backend/imagedetector/`, not connected to the API): `detector.py` (Smaug, merged to main); `commfor.py`, `bombek1.py` and `combined.py` (combined score, bands, limits as settings) with tests, on branch `abdullah/image-detector`, pull request not yet opened.

## Testing with your own photos (`check_folder.py`)

On demand, like the humanizer backend: it loads both models only when there are new photos, prints one log line per photo, then exits and frees the memory.

| Step | What to do |
|---|---|
| 1. Add photos | Copy them into `ReviewIt/backend/imagedetector/inbox/` (ignored by git, never committed) |
| 2. Run | `cd backend`, `venv\Scripts\activate`, `python -m imagedetector.check_folder` |
| 3. Read the log | One line per photo: `beach.jpg \| LIKELY REAL \| score -4.21 \| smaug 0.0003 \| bombek1 0.3100 \| 83 s` |
| Optional | `--watch` keeps it running and scores photos as they arrive (needs about 4 GB of RAM free; Ctrl+C stops) |

| Item | Value |
|---|---|
| Labels | LIKELY AI (score above -1.74), UNCLEAR (above -3.16 up to -1.74), LIKELY REAL (-3.16 or below) |
| Settings (environment variables) | `IMAGE_INBOX`, `IMAGE_LOG_FILE`, `IMAGE_ACCUSE_CUTOFF`, `IMAGE_CLEAR_CUTOFF`, `IMAGE_RESCAN=1` (score everything again), `HF_HUB_OFFLINE=1` (no network calls) |
| Photos read | `.jpg .jpeg .png .webp .bmp .tif .tiff`, as they are, no conversion. HEIC is reported as not read |
| Done list | `inbox/.done.json`: a photo is scored again only if it changed |
| Log files | Console and `imagedetector/logs/detector.log` |
| Speed | 70 to 280 s per photo on this laptop CPU (the first photo of a run includes about a minute of model loading); depends on free RAM, so close Chrome |
| Check made | Same three photos as the research gave LIKELY AI (+6.54), UNCLEAR (-3.06) and LIKELY REAL (-6.27) |

Keep photos used this way as a fresh test: do not tune any cutoff on them.

## Limits

- 50 AI images: the catch rate has a range of about 10 points.
- Open Images is a common training set; false-alarm rates may look better than they are.
- AI images come from 5 free tiers, one prompt variant per tool, none with people.
- Speeds are from a 7.8 GB RAM laptop; Bombek1 was slowed by low free memory.
