# Image detector: validation test plan

Date: 3 Nov 2026. Goal: a test we can trust before ReviewIt sells an image detector.
The first run (100 OpenFake images, [Smaug result](../results/smaug_openfake_core_crops3_summary.txt)) was a smoke test only: it was small and used the dataset the model's authors benchmark on.

## Test set: 50 real + 50 AI

| | Source | Why |
|---|---|---|
| 50 real | **Open Images** (Hugging Face `vikhyatk/openimages-bbox`, test split): Flickr photos from 2018, 5 per subject, 10 subjects. Picked by `scripts/fetch_openimages_real.py`: no people, short side 640 px+, subject assigned with CLIP zero-shot | Certainly real (predate photorealistic generators), CC BY 2.0 on Flickr. Wikimedia Commons was the first choice but is blocked on the author's network (connection reset, 3 Nov 2026) |
| 50 AI | Generated by us in free tiers of 5 tools (10 images each), from the prompts below | Matches what customers upload; the generator of every image is known |

Both sets cover the same 10 subjects, so the model cannot learn "fakes are all portraits".
Known biases, to state in the final report:
- **Open Images is a very common training set**, so a model may have seen these photos. This makes the false-alarm rate look better than it really is.
- **File format:** the real photos are JPEG (resized to at most 1024 px by the dataset authors), while some AI tools give PNG. A model could learn the format. The JPEG re-save copy (same quality for both classes) is therefore the main result, with the originals as a second view.
- Weak real photos kept: `vehicle_04` (distant boats on water), `street_02` (damaged town), animals are mostly deer and antelope.

Limit: with only 50 real photos, even zero mistakes only shows the false-alarm rate is below about 6%. Good for comparing models, weak for promising a number to customers.

## How to generate the AI images

1. Five tools, one per column below (Copilot was dropped on 3 Nov 2026 because its free tier gives only 3 images; Leonardo.ai replaced it. Ideogram was dropped because it is not free; Recraft replaced it. Keep 5 tools).
2. **Tool k generates prompt variant k of every subject** (10 images per tool). Example: Gemini is tool 2, so it generates `mountain-2`, `coast-2`, ... `vehicle-2`.
3. For each prompt, open a **new chat**, paste the prompt exactly, and take the **first** image. Ready-to-paste versions, which add a request to name the image and not to write text on it, are in [PROMPTS_COPY_PASTE.md](PROMPTS_COPY_PASTE.md). Tools often ignore the naming request, so rename the file by hand if needed. Do not regenerate or edit it. If a tool refuses, note it and use a different tool for that prompt.
4. Download the file with the tool's **download button**. No screenshots, no editing, no converting. Keep visible watermarks as they are; customers will upload those too.
5. Save to `image-detection/test-images/own_test/fake/` named `<tool>__<promptid>.<ext>`, for example `gemini__mountain-2.png`. Tool names: `chatgpt`, `gemini`, `metaai`, `leonardo`, `recraft`.
6. Free tiers have daily limits, so spreading this over a few days is fine. Write down the model version if the tool shows one.

## Running the test (after both folders are filled)

1. A script builds the file list and splits it into a **tuning set (20 real + 20 AI)** and a **final set (30 + 30)**, balanced by subject and tool.
2. Smaug runs on both, on the original files and on three degraded copies (JPEG re-save, downsized, screenshot-style). The cutoff score is chosen on the tuning set only. The final set is run once.
3. The report gives, for the final set: share of AI images caught, share of real photos wrongly flagged, both with 95% ranges, plus results per tool and per degraded copy.
4. If we compare models or a combination, the same split is used for all of them.
